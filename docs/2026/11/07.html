오늘의 기술

Redis 캐싱 전략

커리큘럼 #26 데이터베이스 ⏱ 5분

Redis 캐싱은 자주 읽는 데이터를 메모리 기반 저장소 Redis에 복사해 두고, 느린 원본 DB 대신 빠르게 응답하는 기법입니다.

왜 필요한가

데이터베이스는 디스크와 복잡한 쿼리를 거치기 때문에 같은 조회가 몰리면 응답이 느려지고 DB 자체가 병목이 됩니다. 인기 게시글이나 상품 정보처럼 읽기는 많고 바뀌는 일은 드문 데이터를 매번 DB에서 꺼내는 것은 낭비입니다.

Redis는 데이터를 메모리에 두기 때문에 보통 마이크로초에서 밀리초 단위로 응답합니다. 캐시를 앞에 두면 DB 부하가 줄고 사용자가 느끼는 지연도 짧아집니다. 반대로 캐시가 없으면 트래픽이 늘 때마다 DB를 키우는 수밖에 없어 비용이 급격히 커집니다.

동작 원리

가장 널리 쓰는 방식은 Cache-Aside(룩어사이드) 패턴입니다. 애플리케이션이 캐시를 직접 확인하고 채웁니다.

  1. 요청이 오면 먼저 Redis에서 키를 조회한다
  2. 값이 있으면(캐시 히트) 바로 반환한다
  3. 값이 없으면(캐시 미스) DB에서 읽는다
  4. 읽은 값을 TTL(만료 시간)과 함께 Redis에 저장한다
  5. 데이터가 바뀌면 해당 키를 삭제(무효화)하거나 새 값으로 덮어쓴다

그 밖의 전략도 알아두면 좋습니다.

  • Write-Through: 쓸 때 캐시와 DB를 함께 갱신해 일관성이 높지만 쓰기가 느려진다
  • Write-Behind: 캐시에 먼저 쓰고 DB 반영은 나중에 해서 빠르지만 유실 위험이 있다

Redis는 메모리가 가득 차면 eviction 정책(예: allkeys-lru)에 따라 오래 쓰이지 않은 키부터 지웁니다. TTL에 무작위 값을 더해 두면 많은 키가 동시에 만료되어 DB로 요청이 몰리는 현상(캐시 스탬피드)을 줄일 수 있습니다.

예시

아래는 Python으로 Cache-Aside를 구현한 예시입니다. redis 패키지가 필요하고, load_user_from_db는 실제 DB 조회 함수라고 가정합니다.

import json
import random
import redis

r = redis.Redis(host="localhost", port=6379, decode_responses=True)

def get_user(user_id: int) -> dict:
    key = f"user:{user_id}"
    cached = r.get(key)
    if cached is not None:          # 캐시 히트
        return json.loads(cached)

    user = load_user_from_db(user_id)   # 캐시 미스: DB 조회
    ttl = 300 + random.randint(0, 60)   # 동시 만료 방지용 지터
    r.set(key, json.dumps(user), ex=ttl)
    return user

def update_user(user_id: int, data: dict) -> None:
    save_user_to_db(user_id, data)
    r.delete(f"user:{user_id}")     # 변경 시 캐시 무효화

읽기 경로에서는 히트면 DB를 건드리지 않고, 미스면 DB 결과를 5분 안팎으로 저장합니다. 쓰기 경로에서는 DB를 먼저 갱신한 뒤 키를 지워 다음 읽기가 최신 값을 가져오게 합니다.

언제 쓰고 언제 안 쓰나

쓰면 좋은 경우

  • 읽기가 쓰기보다 훨씬 많은 데이터(상품 상세, 프로필, 설정값)
  • 계산 비용이 큰 결과(집계, 랭킹)
  • 세션이나 일회용 토큰처럼 만료가 자연스러운 데이터

피해야 할 경우

  • 항상 최신이어야 하는 데이터(잔액, 재고 확정)를 무효화 전략 없이 캐시하는 경우
  • 거의 재사용되지 않는 데이터. 메모리만 차지하고 히트율이 낮다
  • Redis를 유일한 저장소로 쓰는 경우. 재시작이나 eviction으로 데이터가 사라질 수 있으므로 원본은 DB에 둔다

캐시를 도입하면 캐시와 DB 사이의 불일치라는 새 문제가 생깁니다. 히트율과 TTL을 모니터링하면서 일관성 요구에 맞게 조절하세요.

오늘의 기술

정규표현식

커리큘럼 #24 언어/도구 ⏱ 5분

정규표현식은 문자열의 일정한 모양을 기호로 표현해, 그 모양에 맞는 부분을 찾고 검증하고 바꾸는 패턴 언어다.

왜 필요한가

텍스트에서 "전화번호처럼 생긴 부분", "이메일 형식인지" 같은 조건을 if와 반복문, 문자열 함수로만 짜면 코드가 길고 읽기 어렵다. 예를 들어 010-1234-5678과 01012345678을 모두 받으려면 분기가 여러 개 필요하다.

정규표현식은 이런 문자열의 모양을 한 줄의 패턴으로 선언하게 해 준다. 검색, 검증, 치환, 파싱을 같은 문법으로 처리할 수 있고, 대부분의 언어와 도구(grep, 에디터, 데이터베이스)가 비슷한 문법을 지원한다. 없다면 단순한 로그 필터링 하나에도 직접 만든 문자열 처리 코드를 매번 새로 짜야 한다.

동작 원리

  1. 패턴을 쓴다: 슬래시 사이에 찾을 규칙을 적는다. 예를 들어 \d{3}-\d{4}는 숫자 3개, 하이픈, 숫자 4개를 뜻한다.
  2. 엔진이 왼쪽부터 훑는다: 문자열의 각 위치에서 패턴이 맞는지 차례로 시험하고, 처음 맞는 곳에서 일치를 보고한다.
  3. 기본 문법을 조합한다: .은 아무 한 글자, \d는 숫자, \w는 글자·숫자·밑줄, [abc]는 괄호 안의 한 글자, ^와 $는 문장의 처음과 끝이다.
  4. 반복을 표현한다: *는 0번 이상, +는 1번 이상, ?는 0 또는 1번, {n,m}은 n~m번 반복이다. 기본은 가능한 한 많이 잡는 탐욕적 방식이다.
  5. 그룹으로 묶어 꺼낸다: ( )로 묶은 부분은 따로 추출할 수 있고, (?P<이름>...)처럼 이름을 붙일 수도 있다.
  6. 실패하면 되돌아간다: 엔진은 앞선 선택이 틀렸다고 판단하면 이전 지점으로 돌아가 다른 경우를 시도한다. 이것을 백트래킹이라 한다.

자주 하는 실수 두 가지

첫째, 탐욕적 반복이다. <.+>를 <b>굵게</b>에 적용하면 <b> 하나가 아니라 문자열 전체가 일치한다. .+ 뒤에 ?를 붙인 <.+?>는 가능한 한 적게 잡아 <b>만 일치시킨다.

둘째, 특수 문자를 이스케이프하지 않는 것이다. 점을 글자 그대로 찾으려면 \.처럼 역슬래시를 붙여야 한다. 그렇지 않으면 .은 아무 글자와 일치한다.

연습 방법

작은 문제부터 직접 패턴을 만들어 보는 것이 가장 빠르다. 예를 들어 전화번호, 우편번호, 시각(HH:MM)처럼 모양이 분명한 값부터 시작해 본다. 패턴을 만들 때마다 일치해야 할 문자열과 일치하지 않아야 할 문자열을 둘 다 적어 두고 시험하면, 너무 넓거나 좁은 패턴을 일찍 찾을 수 있다.

예시

날짜가 들어 있는 로그에서 연·월·일을 뽑아내는 파이썬 예시다. 이름 있는 그룹으로 각 값을 꺼낸다.

import re

log = "2026-11-04 12:30:01 ERROR payment failed (order=A1024)"
pattern = re.compile(r"(?P<year>\d{4})-(?P<month>\d{2})-(?P<day>\d{2}).*order=(?P<order>\w+)")

m = pattern.search(log)
if m:
    print(m.group("year"), m.group("month"), m.group("day"))
    print(m.group("order"))

실행하면 2026 11 04와 A1024가 출력된다. 같은 패턴을 여러 번 쓸 때는 re.compile로 미리 컴파일해 두면 편하다.

언제 쓰고 언제 안 쓰나

쓰면 좋은 경우 - 로그나 텍스트에서 일정한 모양의 값(날짜, ID, 숫자)을 뽑을 때 - 입력 형식을 가볍게 검증하거나 일괄 치환할 때 - 에디터와 터미널에서 빠르게 검색할 때

피해야 할 경우 - HTML, JSON처럼 중첩 구조가 있는 형식은 전용 파서를 쓴다. 정규표현식은 괄호가 몇 겹이든 짝을 맞추는 일에 맞지 않는다. - 이메일 주소의 완전한 검증처럼 규칙이 복잡한 경우는 패턴이 길어지고 틀리기 쉽다. - (a+)+처럼 중첩된 반복은 일치에 실패할 때 백트래킹이 폭발적으로 늘어 서버가 멈출 수 있다(ReDoS). 사용자 입력에 쓰는 패턴은 특히 조심한다. - 패턴이 한 줄로 이해되지 않으면 이름 있는 그룹과 주석, 또는 여러 단계로 나누어 쓴다.

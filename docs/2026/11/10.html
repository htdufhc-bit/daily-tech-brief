오늘의 기술

서버리스

커리큘럼 #29 클라우드/인프라 ⏱ 5분

서버리스는 서버를 직접 관리하지 않고 코드를 이벤트에 반응해 실행하며, 쓴 만큼만 비용을 내는 클라우드 실행 모델이다.

왜 필요한가

웹 서비스를 운영하려면 원래 서버를 사고, 운영체제를 설정하고, 보안 패치를 하고, 트래픽에 맞춰 대수를 조절해야 했다. 사용자가 적은 새벽에도 서버는 켜져 있어 비용이 나가고, 갑자기 트래픽이 몰리면 서버를 늘리기 전에 장애가 난다. 작은 기능 하나를 위해서도 서버 한 대를 관리해야 하는 셈이다.

서버리스는 이 부담을 클라우드 업체에 넘긴다. 이름과 달리 서버가 없는 것이 아니라 개발자가 서버를 보지 않아도 되는 방식이다. 개발자는 비즈니스 로직에만 집중하고, 확장과 가용성은 플랫폼이 맡는다.

흔히 서버리스는 두 가지를 묶어 부르는 말이다. 하나는 코드를 함수 단위로 실행하는 FaaS(AWS Lambda, Google Cloud Functions 등)이고, 다른 하나는 데이터베이스, 인증, 스토리지처럼 운영 부담 없이 쓰는 관리형 백엔드 서비스다.

동작 원리

  1. 개발자가 함수 코드를 작성해 플랫폼에 배포한다. 서버나 컨테이너는 직접 만들지 않는다.
  2. 함수에 트리거를 연결한다. HTTP 요청, 파일 업로드, 큐 메시지, 스케줄 같은 이벤트가 트리거가 된다.
  3. 이벤트가 오면 플랫폼이 빈 실행 환경을 찾아 코드를 올리고 함수를 실행한다. 이때 환경을 새로 만드는 것이 콜드 스타트다.
  4. 함수가 끝나면 환경은 잠시 유지됐다가 사라진다. 그 사이 다시 요청이 오면 기존 환경을 재사용하는 웜 스타트라 훨씬 빠르다.
  5. 트래픽이 늘면 플랫폼이 환경을 병렬로 더 띄운다. 요청이 없으면 0개까지 줄고, 비용은 실행 횟수와 실행 시간만큼만 나온다.

여기서 중요한 성질은 무상태다. 실행 환경은 언제든 사라지므로 함수 안의 변수나 로컬 파일에 상태를 두면 안 된다. 상태는 데이터베이스, 객체 스토리지, 캐시 같은 외부 서비스에 저장한다. 실행 시간(보통 수 분 이내)과 메모리에도 상한이 있다.

예시

AWS Lambda와 Python으로 만든 가장 간단한 HTTP 함수다. 요청의 name 파라미터를 받아 인사말을 JSON으로 돌려준다.

import json

def handler(event, context):
    params = event.get("queryStringParameters") or {}
    name = params.get("name", "world")
    return {
        "statusCode": 200,
        "headers": {"Content-Type": "application/json"},
        "body": json.dumps({"message": f"hello, {name}"}, ensure_ascii=False),
    }

handler는 이벤트가 올 때마다 호출되는 진입점이다. 서버를 띄우는 코드가 없다는 점에 주목하자. 이 함수를 API Gateway 같은 HTTP 트리거에 연결하면 GET /hello?name=kim 요청에 {"message": "hello, kim"}이 응답된다. 데이터베이스 연결처럼 무거운 초기화는 함수 바깥(모듈 최상단)에 두면 웜 스타트에서 재사용된다.

언제 쓰고 언제 안 쓰나

쓰면 좋은 경우

  • 트래픽이 불규칙한 서비스. 평소에는 거의 없다가 이벤트 때 몰리는 경우 비용과 확장 모두 유리하다.
  • 이미지 썸네일 생성, 파일 업로드 후처리, 웹훅 수신, 정기 배치처럼 짧게 끝나는 이벤트 기반 작업.
  • 프로토타입이나 사이드 프로젝트처럼 운영 인력이 부족한 상황.

피하는 게 좋은 경우

  • 응답 지연에 매우 민감한 서비스. 콜드 스타트가 수백 밀리초에서 수 초까지 지연을 만들 수 있다.
  • 오래 실행되거나 상태를 메모리에 계속 들고 있어야 하는 작업. 실행 시간 제한과 무상태 제약에 걸린다.
  • 트래픽이 꾸준히 높은 서비스. 항상 켜져 있는 서버가 호출 횟수 기반 과금보다 오히려 저렴할 수 있다.
  • 특정 업체의 이벤트 형식과 서비스에 깊이 묶이는 벤더 종속이 부담스러운 경우.

처음에는 전체를 옮기기보다 이벤트 처리처럼 경계가 분명한 일부 기능부터 서버리스로 시도해 보는 것이 안전하다.

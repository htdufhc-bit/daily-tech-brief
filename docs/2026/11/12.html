오늘의 기술

비밀번호 해싱

커리큘럼 #31 보안 ⏱ 6분

비밀번호 해싱은 비밀번호를 되돌릴 수 없는 고정 길이 값으로 바꿔 저장하고, 로그인 때 입력값을 같은 방식으로 바꿔 비교하는 방법이다.

왜 필요한가

비밀번호를 평문으로 저장하면 DB가 한 번 유출되는 순간 모든 계정이 그대로 노출된다. 사용자들은 여러 사이트에서 같은 비밀번호를 쓰는 경우가 많아 피해가 다른 서비스로 번진다. 서버는 비밀번호 원문을 알 필요가 없고 "맞는지"만 확인하면 되므로, 원문을 복원할 수 없는 값만 저장하는 것이 기본 원칙이다.

그런데 SHA-256 같은 일반 해시 함수는 빠르게 계산되도록 설계돼 있다. GPU 하나로 초당 수십억 번 대입할 수 있어, 유출된 해시를 사전 공격으로 금방 깨뜨릴 수 있다. 그래서 비밀번호용으로는 일부러 느리고 메모리를 많이 쓰는 전용 알고리즘이 따로 만들어졌다.

동작 원리

  1. 사용자가 가입하면 서버는 솔트라는 임의의 값을 새로 만든다.
  2. 비밀번호와 솔트를 해시 함수에 넣어 해시를 계산한다. 이때 비용 매개변수(반복 횟수, 메모리 양)로 일부러 계산을 느리게 만든다.
  3. 솔트, 매개변수, 해시를 한 문자열로 묶어 DB에 저장한다.
  4. 로그인할 때는 저장된 솔트와 매개변수를 꺼내 입력값을 같은 방식으로 해시하고, 결과가 같은지 상수 시간 비교로 확인한다.
  5. 하드웨어가 좋아지면 비용 매개변수를 올리고, 로그인 성공 시 새 매개변수로 다시 해시해 저장한다.

솔트는 사용자마다 다른 무작위 값이라 같은 비밀번호도 다른 해시가 된다. 그래서 미리 계산해 둔 표(레인보우 테이블)가 소용없고, 공격자는 사용자마다 따로 계산해야 한다.

비용 매개변수는 해시 한 번에 드는 시간을 정한다. 정상 로그인은 0.1초가 더 걸려도 문제없지만, 초당 수십억 번을 시도하는 공격자에게는 치명적이다.

대표 알고리즘은 다음과 같다.

  • bcrypt: 오래 검증됐고 널리 지원된다. 입력이 72바이트로 잘리는 제한이 있다.
  • scrypt: 메모리를 많이 쓰게 해 GPU·ASIC 공격 비용을 높인다.
  • Argon2id: 메모리·시간·병렬도를 조절할 수 있는 최신 표준으로, 새 시스템의 1순위로 권장된다.

예시

파이썬 표준 라이브러리만으로 scrypt 해싱과 검증을 구현한 예시다. 저장 형식은 솔트$해시이며 둘 다 16진수 문자열이다.

import hashlib, hmac, os

N, R, P = 2**14, 8, 1  # 비용 매개변수 (메모리 약 16MB)

def hash_password(password: str) -> str:
    salt = os.urandom(16)
    digest = hashlib.scrypt(password.encode(), salt=salt, n=N, r=R, p=P)
    return salt.hex() + "$" + digest.hex()

def verify_password(password: str, stored: str) -> bool:
    salt_hex, digest_hex = stored.split("$")
    digest = hashlib.scrypt(password.encode(), salt=bytes.fromhex(salt_hex), n=N, r=R, p=P)
    return hmac.compare_digest(digest, bytes.fromhex(digest_hex))

stored = hash_password("correct horse battery staple")
print(verify_password("correct horse battery staple", stored))  # True
print(verify_password("wrong", stored))                         # False

같은 비밀번호를 두 번 해싱해 보면 솔트가 달라서 저장값도 다르다. 실무에서는 직접 만들기보다 argon2-cffi, bcrypt 같은 검증된 라이브러리를 쓰는 편이 안전하다. 라이브러리는 매개변수까지 해시 문자열에 담아 주기 때문이다.

언제 쓰고 언제 안 쓰나

써야 하는 경우: 사용자가 입력한 비밀번호를 서버가 검증만 하면 되는 모든 서비스. 새 프로젝트라면 Argon2id를 먼저 고려하고, 플랫폼 제약이 있으면 bcrypt나 scrypt를 쓴다. 해시 비용은 서버에서 로그인 한 번에 대략 0.1~0.5초가 걸리는 수준으로 맞추는 것이 보통이다.

피해야 하는 경우 - MD5, SHA-1, 솔트 없는 SHA-256처럼 빠른 해시를 단독으로 쓰는 것 - 직접 만든 해시 방식이나 "해시를 여러 번 겹치는" 임시 방식 - API 키처럼 길고 무작위인 비밀값에 느린 해시를 쓰는 것. 이런 값은 추측이 불가능하므로 SHA-256 같은 빠른 해시로 충분하다. - 비밀번호 복원이 필요한 기능. 해시는 되돌릴 수 없으므로, 재설정 링크 방식으로 바꿔야 한다.

해싱만으로 모든 위험이 사라지지는 않는다. 로그인 시도 횟수 제한, 다중 인증, 유출 비밀번호 검사를 함께 적용해야 한다.

오늘의 기술

데드락

커리큘럼 #20 운영체제 ⏱ 5분

데드락(교착 상태)은 둘 이상의 작업이 서로가 가진 자원을 기다리느라 영원히 진행하지 못하는 상태다.

왜 필요한가

여러 스레드나 프로세스가 같은 자원(파일, DB 행, 락)을 함께 쓰려면 상호 배제가 필요하고, 그래서 락이 생겼다. 그런데 락을 여러 개 쓰기 시작하면 새로운 문제가 생긴다. 서로 상대가 쥔 락을 기다리면 둘 다 영영 깨어나지 못한다.

데드락은 에러 메시지 없이 프로그램이 그냥 멈춘다는 점이 까다롭다. CPU 사용률도 낮고 로그도 조용해서 원인을 찾기 어렵다. 그래서 발생 조건을 이해하고 설계 단계에서 피하는 것이 중요하다.

인천공항 발권 시스템처럼 여러 시스템이 얽힌 환경에서도 자원 대기 문제는 장애의 흔한 원인이다.

동작 원리

데드락은 아래 네 가지 조건이 동시에 성립할 때만 발생한다 (코프만 조건).

  1. 상호 배제: 자원을 한 번에 한 작업만 쓸 수 있다.
  2. 점유와 대기: 자원을 하나 쥔 채로 다른 자원을 기다린다.
  3. 비선점: 다른 작업이 쥔 자원을 강제로 빼앗을 수 없다.
  4. 순환 대기: A는 B를, B는 A를 기다리는 식으로 대기가 원을 이룬다.

동작 예시는 이렇다.

  1. 스레드 1이 락 A를 얻는다.
  2. 스레드 2가 락 B를 얻는다.
  3. 스레드 1이 락 B를 요청하지만 스레드 2가 쥐고 있어 기다린다.
  4. 스레드 2가 락 A를 요청하지만 스레드 1이 쥐고 있어 기다린다.
  5. 둘 다 상대가 놓아 주기를 기다리며 영원히 멈춘다.

네 조건 중 하나만 깨도 데드락은 생기지 않는다. 가장 현실적인 방법은 순환 대기를 깨는 것으로, 모든 스레드가 락을 항상 같은 순서로 얻도록 약속한다. 그 밖에 타임아웃을 두고 실패하면 가진 락을 놓고 재시도하거나(점유와 대기 완화), 데이터베이스처럼 데드락을 감지해 한쪽 트랜잭션을 강제로 롤백하는 방법(비선점 완화)이 있다.

예시

아래 파이썬 코드는 두 스레드가 락을 반대 순서로 잡아 데드락이 생기는 상황이다. 실행하면 두 스레드가 서로를 기다리며 멈춘다.

import threading, time

lock_a = threading.Lock()
lock_b = threading.Lock()

def worker1():
    with lock_a:
        time.sleep(0.1)
        with lock_b:
            print("worker1 done")

def worker2():
    with lock_b:
        time.sleep(0.1)
        with lock_a:
            print("worker2 done")

t1 = threading.Thread(target=worker1)
t2 = threading.Thread(target=worker2)
t1.start(); t2.start()
t1.join(); t2.join()

고치는 방법은 두 스레드 모두 lock_a를 먼저, lock_b를 나중에 잡도록 순서를 통일하는 것이다. 이렇게 하면 순환 대기가 사라진다.

def worker2():
    with lock_a:      # 순서를 worker1과 똑같이 맞춘다
        time.sleep(0.1)
        with lock_b:
            print("worker2 done")

언제 쓰고 언제 안 쓰나

알아 두면 좋은 경우: 락을 두 개 이상 동시에 쥐는 코드를 쓸 때, DB 트랜잭션에서 여러 행을 갱신할 때, 서비스끼리 서로를 호출하며 대기하는 구조를 설계할 때.

피하는 방법: 가능하면 락을 하나만 쓰거나 락 범위를 짧게 유지한다. 여러 락이 필요하면 전역 순서를 정하고, 락 안에서 외부 호출처럼 오래 걸리는 작업을 하지 않는다. 타임아웃이 있는 락 획득(acquire(timeout=...))도 안전망이 된다.

주의: 운영체제가 데드락을 막으려고 모든 상황을 검사하면 비용이 크기 때문에, 일반 운영체제는 대개 데드락을 직접 막지 않고 개발자에게 맡긴다(타조 알고리즘). 반면 DB는 데드락을 감지해 한쪽을 롤백한다. 롤백된 트랜잭션은 재시도하도록 코드를 작성해야 한다.

오늘의 기술

도커 컨테이너

커리큘럼 #5 클라우드/인프라 ⏱ 5분

도커 컨테이너는 애플리케이션과 실행 환경을 하나로 묶어, 호스트 커널을 공유하면서도 다른 프로세스와 격리된 채 실행하는 단위다.

왜 필요한가

"내 컴퓨터에서는 되는데 서버에서는 안 돼요"라는 말을 들어 본 적이 있을 것이다. 운영체제, 라이브러리 버전, 설정이 조금만 달라도 같은 코드가 다르게 동작하기 때문이다.

예전에는 가상 머신(VM)으로 환경을 통째로 복제했지만, VM은 운영체제 전체를 부팅해야 해서 용량이 크고 시작이 느리다. 컨테이너는 필요한 만큼만 격리해서 이 문제를 가볍게 해결한다. 개발·테스트·운영 환경이 같은 이미지를 쓰므로 환경 차이로 생기는 문제가 크게 줄고, 한 서버에 여러 서비스를 촘촘하게 올릴 수도 있다.

컨테이너가 없다면 서비스마다 서로 충돌하는 라이브러리 버전을 한 서버에서 맞춰야 하고, 새 서버를 준비할 때마다 설치 절차를 사람이 반복해야 한다.

동작 원리

  1. 이미지: 애플리케이션과 그 실행에 필요한 파일·라이브러리를 읽기 전용 계층(layer)으로 쌓아 묶어 둔 패키지다. Dockerfile로 만든다.
  2. 컨테이너 생성: docker run을 하면 이미지 위에 쓰기 가능한 계층이 하나 얹히고, 이것이 컨테이너가 된다.
  3. namespace로 격리: 리눅스 커널은 프로세스마다 PID, 네트워크, 마운트, 호스트 이름 같은 자원을 따로 보이게 한다. 그래서 컨테이너 안에서는 자기 프로세스가 PID 1처럼 보이고, 자기만의 파일 시스템과 네트워크 인터페이스를 가진 것처럼 느껴진다.
  4. cgroups로 제한: 컨테이너가 쓸 수 있는 CPU, 메모리, 입출력 양을 상한으로 묶는다. 한 컨테이너가 자원을 독점하는 일을 막는다.
  5. 커널 공유: 가상 머신과 달리 게스트 운영체제를 따로 부팅하지 않고 호스트 커널을 함께 쓴다. 그래서 시작이 빠르고 가볍다.
  6. 레지스트리: 만든 이미지를 Docker Hub 같은 저장소에 올리고 내려받아 어디서든 같은 환경을 재현한다.

예시

간단한 파이썬 웹 서버를 컨테이너로 만드는 Dockerfile이다. 각 줄이 이미지의 계층 하나가 된다.

FROM python:3.12-slim
WORKDIR /app
COPY app.py .
EXPOSE 8000
CMD ["python", "-m", "http.server", "8000"]

이 파일이 있는 폴더에서 아래 명령으로 빌드하고 실행해 본다. -p 8000:8000은 호스트의 8000번 포트를 컨테이너의 8000번 포트에 연결하고, --memory는 cgroups로 메모리 상한을 둔다.

docker build -t hello-web .
docker run --rm -p 8000:8000 --memory 256m hello-web

브라우저에서 http://localhost:8000에 접속하면 컨테이너 안의 서버가 응답한다. --rm을 붙였으므로 종료하면 컨테이너가 자동으로 삭제된다.

언제 쓰고 언제 안 쓰나

쓰면 좋은 경우 - 개발 환경을 팀원 모두가 똑같이 맞추고 싶을 때 - 마이크로서비스처럼 작은 서비스를 여러 개 독립적으로 배포할 때 - CI에서 깨끗한 환경으로 테스트를 돌리고 싶을 때 - 데이터베이스나 메시지 큐를 로컬에서 빠르게 띄워 실험할 때

피해야 하거나 주의할 경우 - 컨테이너는 호스트 커널을 공유하므로 VM만큼 강한 격리를 보장하지 않는다. 신뢰할 수 없는 코드를 돌릴 때는 추가 대책이 필요하다. - 컨테이너를 지우면 안에 쓴 데이터도 사라진다. 보존할 데이터는 볼륨(volume)에 저장해야 한다. - 윈도우 전용 GUI 프로그램처럼 호스트 커널과 다른 환경이 필요한 경우에는 잘 맞지 않는다. - 이미지를 크게 만들거나 루트 권한으로 실행하면 보안과 배포 속도에 부담이 된다. 가벼운 베이스 이미지를 쓰고 일반 사용자로 실행하는 습관을 들이자.

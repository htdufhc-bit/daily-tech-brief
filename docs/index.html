오늘의 기술

AI 에이전트와 도구 호출

커리큘럼 #30 AI/ML ⏱ 5분

대규모 언어 모델(LLM)이 스스로 외부 도구를 골라 호출하고, 그 결과를 보며 목표를 달성할 때까지 단계를 반복하는 방식이 AI 에이전트다.

왜 필요한가

LLM 혼자서는 학습 시점 이후의 정보를 모르고, 정확한 계산을 못 할 때가 있으며, 파일을 읽거나 서비스에 요청을 보내는 일도 할 수 없다. 그저 글자를 이어 쓰는 모델이기 때문이다. 도구 호출은 이 한계를 메우려고 나왔다. 모델은 "어떤 함수를 어떤 인자로 부르고 싶다"는 요청을 구조화해 내놓고, 실제 실행은 바깥의 프로그램이 맡는다. 이렇게 하면 모델은 최신 정보 검색, 코드 실행, 데이터베이스 조회, 외부 서비스 제어까지 할 수 있다. 도구 호출이 없으면 사람이 모델의 답을 보고 직접 복사해서 실행하고 결과를 다시 붙여 넣어야 해서 번거롭고 느리다.

동작 원리

  1. 도구 정의: 개발자가 함수의 이름, 설명, 입력 형식(JSON 스키마)을 모델에 알려 준다.
  2. 모델의 판단: 사용자 요청을 받은 모델이 도구가 필요하다고 판단하면 도구 이름과 인자를 구조화된 형태로 출력한다. 이때 모델이 함수를 직접 실행하지는 않는다.
  3. 실행: 에이전트 프로그램(하네스)이 그 호출을 받아 실제로 함수를 실행한다. 파일 읽기, 검색, API 호출 등이 여기에 해당한다.
  4. 결과 전달: 실행 결과를 대화에 다시 넣어 모델에게 돌려준다.
  5. 반복: 모델이 결과를 보고 다른 도구를 더 부르거나, 충분하다고 판단하면 최종 답을 낸다.

이 순환을 에이전트 루프라고 한다. 루프를 안전하게 운영하려면 최대 반복 횟수, 도구별 권한, 실행 환경의 격리가 필요하다. 모델이 만든 인자는 사용자 입력처럼 믿지 말고 항상 검증해야 한다. 오늘 소개한 토스의 사례처럼 실행 환경을 격리하는 설계도 같은 이유에서 나온다.

예시

아래는 도구 하나(add)를 가진 가장 단순한 에이전트 루프의 뼈대다. call_model은 실제로는 LLM API 호출이며, 여기서는 흐름을 보이기 위해 가짜로 만들었다.

import json

def add(a: int, b: int) -> int:
    return a + b

TOOLS = {"add": add}

def call_model(messages):
    # 가짜 모델: 아직 도구 결과가 없으면 도구를 부르고, 있으면 답한다
    last = messages[-1]
    if last["role"] == "user":
        return {"tool": "add", "args": {"a": 2, "b": 3}}
    return {"answer": f"결과는 {last['content']}입니다."}

messages = [{"role": "user", "content": "2와 3을 더해 줘"}]
for _ in range(5):  # 최대 반복 횟수로 무한 루프를 막는다
    reply = call_model(messages)
    if "answer" in reply:
        print(reply["answer"])
        break
    result = TOOLS[reply["tool"]](**reply["args"])
    messages.append({"role": "tool", "content": json.dumps(result)})

실행하면 결과는 5입니다.가 출력된다. 실제 서비스에서는 call_model 자리에 LLM API를 넣고, 도구 이름이 TOOLS에 있는지, 인자가 스키마에 맞는지 먼저 확인해야 한다.

언제 쓰고 언제 안 쓰나

쓰면 좋은 경우: 최신 정보가 필요하거나, 여러 단계의 조사와 작업을 자동화하거나, 정해진 API와 내부 시스템을 자연어로 다루게 하고 싶을 때 잘 맞는다. 코드 작성 보조, 데이터 분석 반복 작업, 고객 문의 처리 같은 일이 대표적이다.

피해야 할 경우: 결과가 항상 같아야 하는 단순 계산이나 규칙 기반 처리는 일반 코드가 더 빠르고 싸고 정확하다. 결제나 삭제처럼 되돌리기 어려운 작업은 사람의 확인 단계 없이 맡기지 않는 편이 좋다. 에이전트가 읽는 웹 페이지나 문서에 숨은 지시문(프롬프트 인젝션)이 들어 있을 수 있으므로, 권한은 필요한 만큼만 주고 실행 환경을 격리해야 한다.
